# ThreatWatch

ThreatWatch is a lightweight **post-alert security analysis layer built on top of Wazuh**.

It reads alerts generated by Wazuh, parses and normalizes them, performs basic incident correlation, generates security statistics, and exposes the processed information through a Flask API.

> **Note:** ThreatWatch does not replace Wazuh. Wazuh is responsible for event monitoring and alert generation, while ThreatWatch performs additional post-alert processing and analysis.

---

## Architecture

```text
Security Event
      │
      ▼
    Wazuh
      │
      ▼
alerts.json
      │
      ▼
ThreatWatch
      │
      ├── Read
      │
      ├── Parse
      │
      ├── Normalize
      │
      └── Analyze
             │
             ├── Incidents
             │
             └── Statistics
                    │
                    ▼
                Flask API
                    │
                    ▼
             Authorized Client
```

## Requirements

Before running ThreatWatch, make sure the system has:

- Linux
- Python 3
- Wazuh Manager
- Git
- Flask

ThreatWatch currently reads the Wazuh alert file from:

```text
/var/ossec/logs/alerts/alerts.json
```

Therefore, the alert-processing component currently runs on the system where the Wazuh Manager and its alert file are available.

---

## 1. Check Wazuh Installation

Check whether Wazuh Manager is installed:

```bash
sudo systemctl status wazuh-manager --no-pager
```

If Wazuh is installed and running, you should see:

```text
Active: active (running)
```

If it is installed but stopped, start it:

```bash
sudo systemctl start wazuh-manager
```

To verify again:

```bash
sudo systemctl status wazuh-manager --no-pager
```

### If Wazuh is not installed

ThreatWatch depends on Wazuh for generating security alerts.

Install Wazuh by following the official Wazuh documentation:

https://documentation.wazuh.com/current/installation-guide/index.html

After installation, verify that the alert file exists:

```bash
sudo ls -lh /var/ossec/logs/alerts/
```

You should find:

```text
alerts.json
```

## 3. Create a Virtual Environment

Create the Python virtual environment:

```bash
python3 -m venv .venv
```

Activate it:

```bash
source .venv/bin/activate
```

After activation, your terminal should show something similar to:

```text
(.venv) user@machine:~/Threatwatch$
```

## 4. Install Dependencies

Install the required Python packages:

```bash
pip install -r requirements.txt
```

The current project uses Flask for the API layer.

---

## 5. Verify Wazuh Alerts

Before running ThreatWatch, check whether Wazuh has generated alerts:

```bash
sudo ls -lh /var/ossec/logs/alerts/alerts.json
```

You can also inspect recent alerts:

```bash
sudo tail -n 5 /var/ossec/logs/alerts/alerts.json
```

The file contains **JSON Lines (NDJSON)** data, where each line represents a Wazuh alert.

## 6. Run the ThreatWatch Terminal Demo

Run:

```bash
python app.py
```

The terminal demonstration performs the complete local processing workflow:

1. Read Wazuh alerts
2. Parse alert data
3. Normalize alerts
4. Detect basic incidents
5. Generate severity statistics
6. Display recent alerts
7. Display detected incidents

Example:

```text
========== THREATWATCH ==========

[1] Reading Wazuh alerts...
    Raw alerts found: ...

[2] Parsing and normalizing alerts...
    Valid alerts processed: ...

[3] Detecting incidents...
    Incidents detected: ...

[4] Statistics...

[6] Detected incidents:

========== DEMO COMPLETE ==========
```

The exact numbers depend on the alerts currently present in the Wazuh alert file.

## 7. Run the Flask API

ThreatWatch also provides a Flask API for accessing the processed information.

Start the API with:

```bash
python -c "from app import create_app; create_app().run(host='0.0.0.0', port=5000)"
```

The application listens on port `5000`.

### Available Endpoints

| Endpoint | Purpose |
|----------|---------|
| `/` | Basic project status |
| `/health` | Health check |
| `/alerts` | Returns normalized Wazuh alerts |
| `/statistics` | Returns alert and incident statistics |

For example:

```bash
curl http://127.0.0.1:5000/health
```

or:

```bash
curl http://127.0.0.1:5000/incidents
```

The API can also be accessed from another device when the Linux machine and client are on a reachable network and the required network access is allowed.

## 8. Testing with an SSH Authentication Event

ThreatWatch can be tested by generating a security event that Wazuh can detect.

From another machine on the same network, attempt an SSH login to the monitored Linux machine using an incorrect password:

```bash
ssh username@<LINUX-IP>
```

After the failed authentication attempt, check whether Wazuh generated new alerts:

```bash
sudo tail -n 10 /var/ossec/logs/alerts/alerts.json
```

Then run:

```bash
python app.py
```

ThreatWatch will process the generated Wazuh alerts.

Depending on the test, Wazuh may generate alerts related to:

- Failed authentication
- Non-existent user login attempts
- Multiple failed password attempts
- SSH brute-force activity

## 9. Incident Correlation

The current MVP uses a simple **source-IP-based correlation strategy**.

Multiple alerts from the same source IP can be grouped into a single incident.

```text
Source IP
   │
   ├── Alert 1
   ├── Alert 2
   ├── Alert 3
   └── Alert 4
          │
          ▼
       Incident
```

The incident severity is based on the highest severity among the grouped alerts.

This is intentionally a basic MVP approach and is not intended to represent a production-grade correlation engine.

## 11. Current Limitations

The current version is a learning-oriented MVP.

- Correlation is currently based mainly on source IP.
- Alerts without source IP information require limited correlation handling.
- No persistent database is used.
- The current alert-processing component expects access to a local Wazuh alert file.
- Multi-agent deployment has not been tested.
- The Flask API does not currently implement a complete authentication and authorization mechanism.
- Advanced attack-chain and time-window correlation are not implemented.
- No graphical security dashboard is included.

## Security Note

Do **not** upload real Wazuh logs such as:

```text
/var/ossec/logs/alerts/alerts.json
```

to a public GitHub repository.

Wazuh alerts may contain sensitive information such as:

- IP addresses
- Usernames
- Host information
- Authentication events
- System details

Only use sanitized or sample data in public documentation.
